# M5 plan: the v1 spacecraft

## Goal
One decently detailed, realistic crewed capsule + service module ("RS-1 Corvid"), flown
with real 6-DOF dynamics. The physics core stays generic: the vehicle is a JSON data file
(`data/vehicles/rs1_corvid.json`), with no vehicle-specific code paths.

## Core (`sim-core`)
- **`vehicle`**: the data model (parts with mass properties, tanks, engines, RCS thrusters,
  reaction wheels, solar panels, sensors, stages, limits, model reference), validation,
  and mass properties (mass, CoM, inertia via the parallel-axis theorem) as tanks drain.
- **`rcs_alloc`**: maps a commanded body force + torque to thruster duty cycles in [0, 1],
  by bounded least squares (Lawson–Hanson NNLS followed by scaling to the bounds).
  Translation and rotation stay physically coupled, because every thruster's force *and*
  torque about the current CoM enter the solve.
- **`attitude`**: SAS modes Hold, Prograde/Retrograde, Normal/Anti-normal, Radial in/out,
  Target/Anti-target, Maneuver.
  - Quaternion-error cascade controller (rate-limited outer loop, rate inner loop, gyroscopic
    compensation), with gains scaled by the current inertia tensor.
  - Critically damped (k_d = 4·k_p) at every mass state.
  - Actuator split: reaction wheels first (torque and momentum limits, saturation), then RCS.
    Automatic wheel desaturation uses RCS.
- **`vehicle_sim`**: the 6-DOF simulation.
  - **Active mode** (any actuator working): a coupled ODE of translation, quaternion
    attitude, total body angular momentum, wheel momenta and tank masses, integrated by
    DOP853 between fixed **50 Hz control ticks** (zero-order-hold commands).
  - Forces: the M3 force model plus engine and RCS thrust through the time-varying CoM and
    gravity-gradient torque.
  - Euler's equation in angular-momentum form handles time-varying inertia. Jet damping is
    neglected (documented).
  - **Coast mode** (nothing firing, attitude held or inertial): the M3 trajectory with large
    adaptive steps; attitude is kinematic (the SAS target or inertially fixed).
  - Inputs apply on the fixed tick grid, so results never depend on frame rate. Warp is
    limited in active mode.
  - Engines: thrust and Isp vary with ambient pressure (exit-area model calibrated from the
    sea-level and vacuum values), throttle range, ignition limit, minimum on-time, and
    gimbal trim through the CoM plus pitch/yaw steering.
  - Termination: surface impact, dynamic-pressure limit, stagnation heat-flux limit
    (Sutton–Graves).
  - Staging: separating a stage removes its parts, tanks and thrusters and applies the
    separation Δv.

## Tests
- Mass properties against hand calculations, and CoM shift as tanks drain.
- RCS allocation: a pure-torque request gives ~zero net force and vice versa; requests
  beyond capability scale down without changing direction.
- Reaction wheels saturate; desaturation empties them with RCS while holding attitude.
- SAS settles a 30° slew with < 1% overshoot and no oscillation at full **and** empty propellant.
- Engine: achieved Δv vs Tsiolkovsky for the vehicle; sea-level vs vacuum thrust; ignition
  limit and minimum on-time enforced.
- Torque-free rotation conserves angular momentum (wheels just trade momentum with the body).
- Determinism: the same input log gives bit-identical results with different frame chunking.

## Web
- glTF model (`web/public/models/rs1_corvid.glb`) generated by a script from the **same
  JSON**, so the engine bell, RCS quads, panels and docking port sit exactly where the
  physics puts them. PBR materials.
- Engine plume and RCS puffs driven by actual thrust and duty, placed at each thruster.
- HUD: navball (prograde/retrograde/normal/radial/target markers), speed in orbital / surface /
  target modes, altitude, propellant gauges per tank, Δv remaining and burn time, SAS mode,
  wheel saturation, engine state.
- Controls: keyboard (rotation, translation, throttle, SAS modes, engine ignition, staging),
  gamepad and HOTAS through the Gamepad API, with configurable axes.
